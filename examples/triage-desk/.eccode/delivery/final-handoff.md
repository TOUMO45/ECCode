# Final Handoff — TriageDesk

**Idea:** A small web app for a support team: an agent pastes an incoming customer support ticket, and an AI feature classifies it (category, urgency), writes a one-sentence summary and suggests a first reply; the agent reviews and edits the suggestion. Must stay safe against prompt injection in ticket text, work without an API key via a clearly labelled deterministic fallback, and have an evaluation suite with explicit thresholds. Keep it small: Node.js, no database, single-page UI.

## Decisions

- **ARCH-8 zero runtime dependencies** — Adopt zero runtime npm dependencies for the demo app (orchestrator decision, reversible; pending user confirmation). _Rationale:_ The idea says keep it small; zero deps removes supply-chain surface and install steps; costs: raw fetch instead of the official SDK (mitigated by ARCH-2 schema checks).

## Risks

- **RISK-1** [high, open] Prompt injection in ticket text manipulates classification/reply or leaks system prompt; residual: fallback keyword steering — mitigation: NFR2 controls (fixed prompt with marker, redacted+neutralised ticket, no tools, restricted json_schema, V1-V4), detector flag + UI warning, fallback drops detector-matched sentences before scoring, metrics injection_leak=0 / injection_steer (fallback<=0.25, live 0) / attack_success on >=20 attacks incl >=2 held-out families reported as 'k failures in N'; residual: fallback keyword steering, covered by flag + human review
- **RISK-2** [high, open] Automation bias: agents send drafts unread or mistake fallback output for AI output — mitigation: Permanent text source label + fallback reason, injection warning, copy-only (no send), 'not AI-generated' wording tested (AC5)
- **RISK-3** [medium, open] Live model (Haiku 5.5) slow/unavailable/refuses/truncates (adaptive thinking counts toward max_tokens)/returns invalid output — mitigation: 20s timeout, single attempt, effort low explicit, max_tokens 2048 with rationale (configurable), truncated reason+count, non-2xx -> model_error, V1-V4 validator, deterministic fallback with reason, fallback_rate and raw_model_validity metrics
- **RISK-4** [medium, open] Eval not meaningful: fallback rules overfit a small same-team dataset, or dataset edited after rules exist — mitigation: Dataset by test-engineer: >=60 benign rows, holdout >=20 with per-class minimums checked by runner; holdout floors (threshold-0.10) enforced with non-zero exit (AC8); dataset+thresholds sha256 recorded as evidence before any rules commit and checked by verification gate; N printed per metric
- **RISK-5** [high, open] API key leak or key-spend abuse (incl. DNS rebinding from a malicious web page) via unauthenticated local server — mitigation: Key from env only, never echoed (AC10/AC14); Host allowlist (127.0.0.1/localhost/[::1]:PORT) + Origin check before body parsing, no CORS headers (NFR3, AC17); bind 127.0.0.1; body and max_tokens caps; one call per request. Likelihood re-rated Low after Host/Origin check (inherent Medium); impact High. Auth + rate limiting required before non-local deployment
- **RISK-6** [medium, open] Ticket PII logged locally or sent to third party without awareness — mitigation: Metadata-only logs tested with marker (AC10), no persistence, R11 redaction of emails/phones/Luhn-valid cards before live call (AC16), live-mode notice naming redacted classes and what is not removed
- **RISK-7** [medium, open] Model id / Messages API surface (claude-haiku-5-5, output_config.format restricted schema, effort) checked against docs only, not live — mitigation: Model via ANTHROPIC_MODEL, /api/health reports model, restricted schema keyword allowlist + AC9 schema walk, any non-2xx -> model_error visible in UI (AC4 c-f), first live call confirms, unverified status reported honestly
- **RISK-8** [medium, open] XSS via ticket or model text rendered as HTML — mitigation: textContent-only rendering, CSP default-src 'self' without inline script, grep check for HTML sinks (AC11)
- **RISK-9** [medium, open] Redaction misses: unusual phone/card formats, obfuscated emails and unredacted classes (names, addresses, account ids) reach Anthropic; over-redaction lowers live accuracy — mitigation: Ordered deterministic patterns email->Luhn card->phone with binding test vectors (R11, AC16, ev:ev-muylz82a-01c7d490); UI notice states redacted classes and that others are not removed; fallback mode sends nothing; per-class counts logged without content; user may decline live mode
- **RISK-10** [low, mitigated] Output validator V2 (and V1 boundary regex) is O(n^2) on long, attacker-steerable model output: validateTriage runs V2 on summary/suggestedReply of any length, ~0.5 s at 8k chars and 5-8 s at 32k chars (TRIAGE_MAX_TOKENS up to 16000) blocking the single-threaded server — mitigation: Provider length gate before validateTriage (summary<=200, reply<=1200): 32k adversarial output 8301ms -> 1.87ms (ev-muypnaj3-01d37d63). Other validateTriage callers remain exposed; schema-level gate recommended later.
- **RISK-11** [medium, open] npm start under dash does not exec node: SIGTERM to npm alone orphans the server — mitigation: Document running 'node src/server.js' directly under process managers (t16 README); change start script to 'exec node src/server.js' in a later revision (package.json is owned by approved phase foundation)
- **RISK-12** [medium, accepted] Fallback holdout high-urgency recall 0.571 (n=7) below 0.70 floor in the first full-mode eval — mitigation: User decision 2026-10-08: accept holdout high_urgency_recall 0.571 (n=7) < 0.70 as a known limitation of the deterministic fallback for this release; Success Criterion 2 / AC8 holdout floor amended for this release only; the fallback is a labelled safety net, the live model is the intended classifier (live evals NOT RUN, RISK-7).
