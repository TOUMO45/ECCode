# Limits register

Every limit stated or found during the senior-engineering upgrade (v0.2.0 → v0.5.x) gets a row and a disposition:

- **Closed — eliminated:** the limit no longer exists, and the evidence shows it.
- **Closed — by design:** the behavior is intended, and it is disclosed where it applies.
- **Open — mitigated:** the limit remains; its containment is named.
- **Open — named:** the limit remains; the tool reports it instead of hiding it.

An independent audit on 2026-10-23 checked every row against the code. It found an earlier version of this register overclaimed ("nothing is open"), and that one security claim was false (MCP mode had a general shell through `evidence_run`). The rows below include everything that audit found and how each item was handled. **One limit is open** (row 59): the engine's effect on correctness, which the engine batches could not show because the bare agents made no mistakes to catch. Row 56, engine runs that stopped before delivery, closed under its pre-registered rule (19 of 20 delivered). Row 32, the last engine limit, closed when installs became enforced by default: the OS sandbox where Claude Code has one, otherwise no shell at all. Row 36, a measured result (the lean-change skill made Sonnet's total diffs larger), closed by design under the decision rule a follow-up batch registered before it ran: the extra lines are tests, and the code itself is smaller.
