# Limits register

Every limit stated or found during the senior-engineering upgrade (v0.2.0 → v0.5.x) gets a row and a disposition:

- **Closed — eliminated:** the limit no longer exists, and the evidence shows it.
- **Closed — by design:** the behavior is intended, and it is disclosed where it applies.
- **Open — mitigated:** the limit remains; its containment is named.
- **Open — named:** the limit remains; the tool reports it instead of hiding it.

An independent audit on 2026-10-23 checked every row against the code. It found an earlier version of this register overclaimed ("nothing is open"), and that one security claim was false (MCP mode had a general shell through `evidence_run`). The rows below include everything that audit found and how each item was handled. **Eighteen limits are open** (rows 59, 69, 70, 74, 76, 78, 87, 91, 94, 96, 101, 104, 108, 117, 118, 119, 120, 121). Three predate the Mealie pilot:
- **Row 59, the engine's effect on correctness.** Neither the engine suite nor twenty real bugs could show it, because the bare agents made no mistakes to catch. On a real project the bare agent did better.
- **Row 69, the debug track's cost,** which missed its rule as the lighter mode.
- **Row 70, benchmark containment.** Agents' file tools can reach outside their sandbox.

The pilot, ECCode's first test on a real project, added rows 72–108. Its rerun on fresh items at the fix commit (bench/pilot-results/2026-10-25-mealie-rerun.md) closed three of its five engine results:
- false refusals, now 0.64 per item (row 105);
- the long-lived record's lesson (row 106);
- the no-shell item, 2 of 2 (row 107).

Two stay open:
- delivery, 7 of 20 in the registered reading (row 104);
- the greenfield chains (row 108).

The rerun added rows 109–124. Eleven are defects it or the review of its fixes found, each fixed with a test that failed first. Five are named limits:
- the guard's whole-line identity rule (row 117);
- `mv` into a directory (row 118);
- lessons shown but not used (row 119);
- a rework deadlock (row 120);
- the request not citable in a review (row 121).

The pilot's other named limits stand: impact's share of the suite (row 74), unmeasured route-removal recall (row 76), the operators `mutate` lacks (row 78), checks that run one at a time (row 87), the guard's program-and-record rule (row 91), plans with checks that cannot pass yet (row 94), background subagents (row 96) and the benchmark's shared environment (row 101).

Row 56, engine runs that stopped before delivery, closed under its pre-registered rule (19 of 20 delivered). Row 32, the last engine limit, closed when installs became enforced by default: the OS sandbox where Claude Code has one, otherwise no shell at all. Row 36, a measured result (the lean-change skill made Sonnet's total diffs larger), closed by design under the decision rule a follow-up batch registered before it ran: the extra lines are tests, and the code itself is smaller.
