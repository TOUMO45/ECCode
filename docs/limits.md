# Limits register

Every limit stated or found during the senior-engineering upgrade (v0.2.0 → v0.5.x) gets a row and a disposition:

- **Closed — eliminated:** the limit no longer exists, and the evidence shows it.
- **Closed — by design:** the behavior is intended, and it is disclosed where it applies.
- **Open — mitigated:** the limit remains; its containment is named.
- **Open — named:** the limit remains; the tool reports it instead of hiding it.

An independent audit on 2026-10-23 checked every row against the code. It found an earlier version of this register overclaimed ("nothing is open"), and that one security claim was false (MCP mode had a general shell through `evidence_run`). The rows below include everything that audit found and how each item was handled. **Thirty-four limits are open** (rows 59, 69, 70, 74, 76, 78, 87, 91, 94, 96, 101, 108, 117, 118, 119, 120, 121, 126, 136, 137, 138, 139, 140, 141, 142, 144, 145, 146, 147, 148, 149, 151, 152, 154). Three predate the Mealie pilot:
- **Row 59, the engine's effect on correctness.** Neither the engine suite nor twenty real bugs could show it, because the bare agents made no mistakes to catch. On a real project the bare agent did better. The proof run looked for its mistakes on purpose, on every eligible change of fresh Mealie history, and found none the engine could catch. The multi-file run found them on large changes, but the engine's runs on one of its three hard items timed out, and the comparison missed its rule.
- **Row 69, the debug track's cost,** which missed its rule as the lighter mode.
- **Row 70, benchmark containment.** Agents' file tools can reach outside their sandbox.

The pilot, ECCode's first test on a real project, added rows 72–108. Its rerun on fresh items at the fix commit (bench/pilot-results/2026-10-25-mealie-rerun.md) closed three of its five engine results:
- false refusals, now 0.64 per item (row 105);
- the long-lived record's lesson (row 106);
- the no-shell item, 2 of 2 (row 107).

Two stayed open:
- delivery, 7 of 20 in the registered reading (row 104), since closed by the proof run;
- the greenfield chains (row 108).

The rerun added rows 109–130. Sixteen are defects it, its Part A or the review of its fixes found, each fixed with a test that failed first. Among them are four Part A instruments that could not see what they measured, the route table above all (row 127), and routes on routers of other names that compat could not see (row 129). Six are named limits:
- the guard's whole-line identity rule (row 117);
- `mv` into a directory (row 118);
- lessons shown but not used (row 119);
- a rework deadlock (row 120);
- the request not citable in a review (row 121);
- migration edits reported whatever they change (row 126).

The proof run (bench/pilot-results/2026-10-26-mealie-proof.md) took every eligible change of a fresher window, 19 items, twice bare and twice through the engine. The bare agent was wrong only where the request was (row 59 stays open), and every engine run delivered with a clean audit, closing row 104 under its pre-registered rule. It found three defects, each fixed with a test that failed first (rows 131–133), and one more instance of row 91.

The multi-file run (bench/pilot-results/2026-10-27-mealie-multifile.md) took the 16 largest eligible changes of Mealie's recent history. The bare agent got three of them wrong, and on those the engine passed 12 of 18 stage-2 runs against the bare agent's 9 of 18 (p = 0.50, missed; row 59 stays open). Half of its engine runs delivered, against the 80% rule (row 138, open). It added rows 134–138: two engine defects, fixed with tests that failed first; a harness defect, fixed for single runs but not in greenfield chains (row 136, mitigated); a timed-out run's unknown cost (row 137, mitigated); and delivery on large changes. It also added `ps` to the guard's read-only list (row 91).

Phase 2 (the Debugging Lab and the behavior diff, docs/debugging-lab.md and docs/behavior-diff.md) added rows 139–154: rows 152 and 153 for the test-outcome invariant, and row 154 for a process incident, the seed key that reached the implementer after a refused read: eleven named or mitigated limits of the new tools (Python-only localization, SBFL's blind spots, bisect's preconditions, probe placement, the diff-based test rule, FastAPI-only probes, stateful probes, generated inputs, two-run nondeterminism, the unbuilt third probe source, the unmeasured effect) and two by design (the budget's units, routing's reach). Two were found by the fixtures' first run and fixed with the fixture as the test: bisect blaming the first commit when the command was not runnable (row 141), and deletion probes hiding an endpoint's change (row 146).

The pilot's other named limits stand: impact's share of the suite (row 74), route-removal recall on too few removals (row 76), the operators `mutate` lacks (row 78), checks that run one at a time (row 87), the guard's program-and-record rule (row 91), plans with checks that cannot pass yet (row 94), background subagents (row 96) and the benchmark's shared environment (row 101).

Row 56, engine runs that stopped before delivery, closed under its pre-registered rule (19 of 20 delivered). Row 32, the last engine limit, closed when installs became enforced by default: the OS sandbox where Claude Code has one, otherwise no shell at all. Row 36, a measured result (the lean-change skill made Sonnet's total diffs larger), closed by design under the decision rule a follow-up batch registered before it ran: the extra lines are tests, and the code itself is smaller.
