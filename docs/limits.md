# Limits register

Every limit stated or found during the senior-engineering upgrade (v0.2.0 → v0.5.x) gets a row and a disposition:

- **Closed — eliminated:** the limit no longer exists, and the evidence shows it.
- **Closed — by design:** the behavior is intended, and it is disclosed where it applies.
- **Open — mitigated:** the limit remains; its containment is named.
- **Open — named:** the limit remains; the tool reports it instead of hiding it.

An independent audit on 2026-10-23 checked every row against the code. It found an earlier version of this register overclaimed ("nothing is open"), and that one security claim was false (MCP mode had a general shell through `evidence_run`). The rows below include everything that audit found and how each item was handled. **No limit is open.** Row 32, the last one, closed when installs became enforced by default: the OS sandbox where Claude Code has one, otherwise no shell at all.

| # | Limit | Disposition | Evidence |
|---|---|---|---|
| 1 | Obfuscated shell commands (an interpreter writing a record path built from strings, for example) could write the record past the textual guard | Closed — eliminated | The sandboxed profile (`eccode install --sandbox`) makes the record read-only to every shell command and its children at the OS level, through Claude Code's sandbox with `failIfUnavailable` and no unsandboxed retry. Only the per-role MCP servers write it. Live-verified: a runtime-built write failed with EROFS (docs/live/7-sandboxed-profile.txt); profile and role checks are in tests/sandbox-profile.test.js. Without the sandbox: row 32 |
| 2 | ESM `import` bypasses the Node load tracer | Closed — eliminated | scripts/trace/esm-loader.mjs, registered through `module.register` (Node ≥ 18.19 / 20.6). On older runtimes the trace output says ESM imports were not traced. Static and variable-built dynamic import edges are asserted through a symlinked root in tests/codebase.test.js |
| 3 | The static index cannot resolve reflective or dynamic loads in JS/TS and Python | Closed — eliminated | Runtime tracing records importer → target edges for CommonJS `require`, ESM `import`, and Python imports including `importlib` (the Python importer is found by walking the call stack). Asserted in tests/codebase.test.js. Other languages: row 21 |
| 4 | A trace observes only what the traced command exercises | Closed — by design | That is what observation means. The output names every target the command never loaded ("this trace says nothing about the runtime callers of that target"), and static analysis flags dynamic loaders, now including aliased `require` and `createRequire`. A loader that the flag patterns miss, on a branch the command never runs, can still go unseen. The disclosure is pinned in tests/limits.test.js |
| 5 | Small benchmark batches are "a demonstration, not a statistic" | Closed — by design | Reports grade their own n and name the test they used, exact or Monte Carlo (lib/bench.js, pinned in tests/limits.test.js and tests/bench.test.js). Haiku conclusions rest on n≥10–25 batches and the all-data stratified test. **Sonnet-specific conclusions rest only on small samples and are marked unsettled** in their reports |
| 6 | The n=10 replication of the two headline tasks was not significant | Closed — eliminated | A fixed-protocol n=25 replication gave −11 median lines (p = 6.0e-5) and −4 (p ≤ 1.0e-5) (bench/results/2026-10-23-haiku-n25-preregistered.md). The protocol was stated in the working session before the run but not committed in advance. The Monte Carlo fallback was added after the data came in, and the effect estimates do not depend on it |
| 7 | The ask path (`--actor user`) was verified only in unit tests | Closed — eliminated | Live transcript docs/live/6-ask-path.txt: the command was held for the human, the record was unchanged and the audit passed. Identity written through quoting or expansion now fails closed (row 23) |
| 8 | Live verification covered only the trust rows | Closed — eliminated | Each original red/orange row has a dedicated live session, and so do the parts that were first verified only by tests: one runtime-trace session per traced language (docs/live/9-trace-python.txt, docs/live/10-trace-ruby.txt, docs/live/11-trace-php.txt, docs/live/12-trace-java.txt, docs/live/13-trace-kotlin.txt), function-level callers (docs/live/14-function-callers.txt), migrations (docs/live/15-migrations.txt), the refactor track refusing and accepting (docs/live/16-refactor-refused.txt, docs/live/17-refactor-accepted.txt) and the benchmark harness with a real model inside (docs/live/18-bench-real-model.txt). Eighteen transcripts are saved, with the fixtures rebuildable by docs/live/fixtures/build.js; docs/live/README.md lists which earlier sessions' transcripts were not saved |
| 9 | Headline claims about past runs were remembered, not derived | Closed — eliminated | `eccode bench tally` recomputes run counts, hidden-check passes, dependency additions, agent failures, per-batch paired signs and the stratified test from raw runs (lib/bench.js). Doc figures are checked against it in tests/limits.test.js. Per-task medians and p-values come from the same report code and the same raw rows |
| 10 | The across-batch sign test treated repeated batches as independent | Closed — eliminated | Stratified permutation test with labels shuffled within task-batches: −4.57 lines per change, two-sided p ≤ 5.0e-5, seeded (lib/bench.js, tests/bench.test.js) |
| 11 | The installed toolkit under `.claude/` was indexed as project code | Closed — eliminated | The index excludes `.claude/` (lib/codebase.js); regression test in tests/codebase.test.js |
| 12 | The permutation test fell silent above the exact-enumeration cap | Closed — eliminated | Seeded Monte Carlo fallback (100,000 resamples), labelled on each row and in the header (tests/bench.test.js) |
| 13 | Original table, trust row: "Not yet: running the engine as an MCP server" | Closed — eliminated | `eccode mcp --actor <role>`: the actor is locked at startup and no tool takes an actor argument. `evidence_run` runs only approved commands: planned task checks, the behavior command and stack checks. The audit found it previously ran any command; that is fixed and tested in tests/mcp.test.js. What approved commands do is covered by row 20 |
| 14 | Original table, trust row: "Not yet: an automated check on GitHub" | Closed — eliminated | .github/workflows/check.yml: five jobs (Linux on Node 18/20/22, macOS and Windows on Node 22), plus `audit --against` the PR base |
| 15 | Original table, codebase row: "Not yet: a saved map of the codebase for big repos" | Closed — eliminated | The index persists in `.eccode/cache/`, rebuilds incrementally, and is keyed on the parser version (row 22). `eccode mcp` serves it as the `onboard`, `map` and `impact` tools (lib/mcp.js, tests/mcp.test.js) |
| 16 | Original table, codebase row: "Not yet: codebase-memory-mcp integration" | Closed — eliminated | Integrated. `eccode impact --calls` queries codebase-memory-mcp's resolved call graph over MCP stdio (lib/cbm.js) for the function-level callers of every function in the target files. `eccode install --with-codebase-memory` registers it as an MCP server, and the session hook does not flag it as foreign, because its writes go to its own index. Tested at the CLI level; CI installs v0.12.1 pinned by SHA-256 and requires the test (tests/codebase.test.js, tests/sandbox-profile.test.js). Live-verified: docs/live/14-function-callers.txt |
| 17 | Original table, process row: "the full workflow still runs every gate" | Closed — eliminated | Five tracks with their own gates: greenfield runs all of them; quick runs `phase:change` and `verification` (lib/reducer.js, tests/works.test.js) |
| 18 | Original table, deliveries row: "Each project still allows only one delivery" | Closed — eliminated | Work items w1..wN on one record. The endurance test runs 25 seeded consecutive work items on one record, delivering the ones not abandoned: 15, plus w1, with seed 7 (tests/works.test.js) |
| 19 | The runtime trace dropped direct edges from files that were already static dependents | Closed — eliminated | Found by the live impact session. `mergeTrace` now reports every observed edge into the impact set that the static graph lacks (lib/codebase.js; regression test in tests/codebase.test.js; docs/live/2-impact-trace.txt) |
| 20 | Approved commands (`npm test`, for example) execute project code an agent can edit, and could change the record or files outside that agent's ownership | Closed — eliminated | Every evidence command runs inside an integrity window that checks effects, not text. Record changes are reverted and the run fails; tracked files changed outside the caller's claim fail the run and are named (lib/evidence.js; mutation-checked in tests/integrity.test.js). Effects outside the repository are not ECCode's to police |
| 21 | Reflection in Java, Kotlin, Ruby and PHP was not traced at runtime | Closed — eliminated | Runtime tracers: a JVM agent for Java and Kotlin (Class.forName and first use; class names mapped back to .java/.kt sources), a Ruby TracePoint (require, require_relative, autoload, const_get), and a PHP file:// stream wrapper (variable includes, `new $class` autoloads). Each records importer → target edges (scripts/trace/, tests/codebase.test.js). One CI job requires all four languages to run rather than skip. Live-verified, one session per language, each finding the loader edge static analysis missed: docs/live/9-trace-python.txt, docs/live/10-trace-ruby.txt, docs/live/11-trace-php.txt, docs/live/12-trace-java.txt, docs/live/13-trace-kotlin.txt |
| 22 | The index cache was reused across parser changes, keeping stale dynamic-load flags | Closed — eliminated | The cache is keyed on a hash of the parser source (lib/codebase.js); regression test in tests/codebase.test.js |
| 23 | CLI identity written through quoting or shell expansion got past the user-decision ask | Closed — eliminated | The guard unquotes the whole `--actor` word, and shell expansion in eccode arguments is denied inside subagents and asked in the main session (scripts/hooks/guard.js; mutation-checked in tests/guard-fuzz.test.js) |
| 24 | ESM call chains lost upstream callers (single-pass merge, top-down edge order) | Closed — eliminated | `mergeTrace` propagates to a fixpoint; regression test in tests/codebase.test.js |
| 25 | The secrets scan stopped reading `.claude/` after row 11's first fix | Closed — eliminated | The `.claude/` exclusion now applies to the codebase index only; regression test in tests/stack.test.js |
| 26 | Report headers claimed exact p-values when Monte Carlo was used, and floor p-values printed as "=" | Closed — eliminated | The header names the test used, and floors print as "p≤" (lib/bench.js, tests/bench.test.js) |
| 27 | Doc figures drifted from the records (a dated addendum still cited 282 runs) | Closed — eliminated | tests/limits.test.js checks the run and hidden-check figures in the docs against `bench tally` |
| 28 | On Windows, a concurrent writer could exit with an error on transient contention (EPERM/EACCES/EBUSY from a lock file mid-delete or a state file held open) | Closed — eliminated | Found by CI (one Windows job failed `concurrent writers never corrupt the log`). Lock acquisition, atomic rename and JSON reads retry these errors with backoff; other errors still fail fast (lib/util.js). Windows behavior is simulated deterministically on every OS in tests/resume-delivery.test.js |
| 29 | In a sandboxed shell, the eccode CLI waited 10 seconds and failed with a misleading LOCK_TIMEOUT (found by the live sandbox session) | Closed — eliminated | The store checks write access first and fails at once with RECORD_READ_ONLY, pointing to the MCP tools (lib/store.js, tests/sandbox-profile.test.js, docs/live/7-sandboxed-profile.txt) |
| 30 | With one MCP server per role available to every agent, an agent could call another role's server | Closed — eliminated | The guard matches `mcp__eccode_.*` and allows a call only to the caller's own role's server (the main session: orchestrator). The role comes from the tool name, not from any text (scripts/hooks/guard.js, tests/sandbox-profile.test.js) |
| 31 | Shell writes to project files outside an agent's ownership are checked from command text at write time | Closed — by design | Write time is the early warning. The guarantee is at delivery, where content hashes decide: every changed file must be covered by an approved review, and a file modified after approval blocks delivery, however it was written (lib/delivery.js; tests/resume-delivery.test.js, tests/security.test.js) |
| 32 | A project installed without `--sandbox` (or on native Windows, which has no Claude Code sandbox) relied on the textual guard to keep shell commands off the record | Closed — eliminated | `eccode install` now defaults to an enforced profile: `sandbox` where Claude Code supports it, otherwise `no-shell`, where permission rules deny every shell tool (Bash, PowerShell, Monitor). That holds on native Windows too, and the record is written only through the role MCP servers. Live-verified: docs/live/8-no-shell-profile.txt (no Bash tool even when allowed; a Write to the record was refused). The text-only `guard` profile exists only as an explicit opt-out (row 34). Tests: tests/sandbox-profile.test.js |
| 33 | On Windows CI, the PHP, Java and Kotlin tracers recorded no edges: temp paths are 8.3 short names (C:\\Users\\RUNNER~1) that Node keeps but the JVM and PHP expand, so every load fell outside the project root | Closed — eliminated | Found by CI. traceRun passes both spellings of the root (`realpathSync` and `realpathSync.native`), and every tracer accepts either, case-insensitively on Windows (scripts/trace/). A test gives a primary root that matches nothing and the real root as the alternate; every tracer must still record its edges, so the logic is proven on all OSes (tests/codebase.test.js). Confirmed on Windows itself: in the Windows job of the v0.7.0 merge run (github.com/TOUMO45/ECCode/actions/runs/39919370989/job/120300611892), the Ruby, PHP, JVM and Kotlin tracer tests and the two-spellings test ran and passed; the job's only two skips were a POSIX `sh -c` test and pytest |
| 34 | A project may opt out of enforced protection (`--profile guard`) | Closed — by design | An explicit choice, never a default. Every session then says the record has only the text guard and how to reinstall with an enforced profile (scripts/hooks/session-start.js; tests/sandbox-profile.test.js) |
| 35 | MCP servers that ECCode did not install (a filesystem server, for example) run outside the sandbox and the shell deny | Closed — by design | ECCode enforces the surfaces it configures. Every session names the other servers in .mcp.json and the deny rule to add for their file-write tools (scripts/hooks/session-start.js; tests/sandbox-profile.test.js) |

This register is checked by CI as well as written by hand. tests/limits.test.js fails the build if any of these happen:
- a row lacks a valid disposition;
- cited evidence goes missing;
- a by-design disclosure regresses;
- the table breaks;
- a doc figure disagrees with the records.

New limits get a row before the work that states them is called done.
