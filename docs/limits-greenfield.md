# Limits register: Greenfield Senior layer

These limits belong to the additive greenfield layer (`lib/greenfield/`, `bin/eccode-gf.js`). Their ids are placeholders (`L-GF-n`) on purpose: the main register `docs/limits.md` is not edited by this line of work, because the `claude/v3-generalization-fastapi-*` line edits it too (it already claims row 186), and reconciling the two is the owner's task. Dispositions are the register's: **Open, named** (the limit remains and the tool reports it), **Open, mitigated** (the limit remains and its containment is named), **By design**.

Enforcement wording used everywhere in this layer: **prevention on the managed (MCP) path plus guaranteed detection by log-replay audit in all profiles.**

| Id | Limit | Disposition | Slice |
|---|---|---|---|
| L-GF-1 | The layer is additive: the 48 files of the frozen v3 set are not edited, so the plain `eccode` CLI cannot refuse a Greenfield-Senior rule. The layer gives prevention on the managed (MCP) path plus guaranteed detection by log-replay audit in all profiles; a hook adds best-effort write-time checks where the harness runs hooks | Open, mitigated | S1 |
| L-GF-2 | Stack profile v1 is Python / FastAPI / SQLAlchemy / Alembic / SQLite. Other stacks can be built and tested but cannot reach DONE in v1, because the security, api, perf and behavior guards operate on FastAPI only | Open, named | S1 |
| L-GF-3 | Sub-agents of a group share the group's role id and are not individually identified | By design | S2 |
| L-GF-4 | `.eccode/drafts/**` stays a shared scratch area for roles outside the groups, and is namespaced per group for group roles in a Greenfield-Senior project (`.eccode/drafts/<group>/**`, writes only: reads are not intercepted); the orchestrator's dispatch prompt stays an out-of-band channel | Open, named | S2 |
| L-GF-5 | The mock server is stateless; multi-step flows are verified against the real backend at integration | Open, named | S3 |
| L-GF-6 | The artifact validators implement a stated JSON-Schema subset (`lib/greenfield/jsonschema.js`). An unsupported keyword is reported on the nodes the validator visits (not on a branch it never reaches), an unknown `format` is an annotation and is ignored, and a user-supplied `pattern` is not guarded against catastrophic backtracking: S1 never evaluates one (the patterns are the layer's own); S3 must guard them before it evaluates a contract's | Open, named | S1 |
| L-GF-7 | "Hidden" acceptance tests are write-denied and hash-sealed; read-denial depends on the harness running hooks on Read | Open, mitigated | S3 |
| L-GF-8 | The engine cannot detect an undeclared guess, only make a declared one impossible to omit from the report and the ambiguity scan mandatory | Open, named | S4 |
| L-GF-9 | Per-slice design and plan gates are overhead the `feature` track imposes; their measured cost is reported after S4 | Open, named | S4 |

| L-GF-11 | "Behavior diff clean" means no *detected* change: the behavior diff v3 detected 27 of 57 seeded changes (47.4 percent, exact 95 percent interval 34.0 to 61.0) | Open, named | S5 |
| L-GF-12 | Estimates are agent predictions from a single project; no calibration claim until several projects | By design | S4 |
| L-GF-13 | A v4 freeze that absorbs the greenfield layer is deferred until after S5 is stable and has not been started; until then the plain `eccode` CLI is outside the layer | Open, named | S1 |
| L-GF-14 | The cross-file consistency of an *amended* contract bundle (for example a new operation without its access-matrix cells) is checked at slice integration (built in S3, run from S4), not at amendment: an amendment is validated per file, and the approved bundle is re-validated at its sealed bytes from the snapshots | Open, named | S1 |
| L-GF-15 | Between the edit of a sealed contract and the phase review that approves its new bytes, the frozen audit reports the file as modified after approval (its own rule, unchanged); the amendment event explains the change, and the layer's audit stays clean | Open, named | S1 |
| L-GF-16 | A Greenfield-Senior project starts with `eccode-gf init`; an existing ECCode project cannot be adopted in v1 | Open, named | S1 |
| L-GF-17 | The log asserts an event's actor and does not bind it (the frozen engine's own limit, `docs/architecture.md`): a forged event with any actor string is judged by the content rules, which read the actor only where a rule names one (reviewer, group, reviser). **For ownership between groups (S2):** a group cannot act as another on the managed path only while two controls outside the log hold, the per-role server lock with the harness tool list, and the PreToolUse hook; the layer reports which regime is in force (`eccode-gf preflight`, a section of the audit) but cannot see a failure afterwards, and an agent that defeats them is undetectable by the log. What a spoof does not buy: sealed contracts, pinned guard configs and sealed acceptance tests are content-addressed, and any change outside their recorded change paths is detected; a change made through a recorded change path (an amendment or a re-pin by a spoofed reviewer or orchestrator) is recorded, not flagged. Keyed attestation (L-GF-20) is the proposed remedy | Open, named | S1, restated S2 |
| L-GF-18 | The hook reserves the three group role names (`integration-engineer`, `database-engineer`, `security-engineer`) in every ECCode project: a third-party agent of that name is held to the same ownership rules as an implementer | Open, named | S1 |
| L-GF-19 | Slice-closure independence (GF-CLOSE-1) is role-level and record-level: a configured reviewer role that authored nothing in the record. The engine cannot tell two instances of one role apart, so that the review was done by a fresh agent with no context is the orchestrator's dispatch, which the engine cannot read: it records each step's dispatch (role, step, tree, hashed inputs, refused working-record inputs, one review per dispatch) as the orchestrator's attestation. An author's own bypass tests are never recorded as a review pass The role-level record itself holds only while the controls of L-GF-17 hold (design 18.3). | Open, named | S2 |
| L-GF-20 | Proposed, not built: keyed attestation (`gf.attest {seq, hash, role, mac}` after each commit by a role-locked server, key outside the repository) would make a forged actor detectable unless the agent read the key; it needs the key directory read-denied to agents, which depends on the harness running hooks on Read (as L-GF-7). Awaiting the owner's decision; recommended for S5 | Open, named | S2 |
| L-GF-21 | Visual taste is not verified: the UX spec names a design system and the done checks verify states, accessibility and performance budgets where runnable, but whether the result looks good is a judgment no check makes | Open, named | S2 (registered; the UX spec is built in S4a) |
| L-GF-22 | GF-CONF-1 refuses group roles and detects any change after the latest pin, but a re-pin by the orchestrator or the user is accepted with a reason: a loosened configuration re-pinned is recorded and visible, not refused | Open, named | S2 |
| L-GF-23 | A zero-context reviewer receives the tree, and the tree carries the authors' own documents and conclusions (design findings, the evidence file): the dispatch refuses the working record by path, not the authors' views written into tracked files | Open, named | S2 |
| L-GF-24 | In S2 a cross-group file write is refused by the hook on the managed path (design 2.2: for the file tools; a shell write is judged on its command text, L-GF-1), and the audit detects it only when a completion lists the file (GF-OWN-3); a write that no completion lists is found by `eccode-gf attribute` (GF-OWN-4), which joins the audit in S4. With the hook off, such a write is detected only by running that command | Open, named | S2 |
| L-GF-25 | An amendment request has no withdrawal event: a request never applied keeps its contract file writable for the api group, and the check that then matters is GF-FRZ-2 (the bytes against the seal and the amendment chain) | Open, named | S2 |
| L-GF-26 | The closure checks form where it cannot check truth: the accounting numbers are the closer's, copied from the harness; a deferral's limit id is not checked against the register; the battery's test command, base and mutant count are the orchestrator's choice and there is no kill threshold (only the survivors of the last battery need reasons) | Open, named | S2 |
| L-GF-27 | A closure records the tree it names; a commit after it does not undo it, and "no commit after it other than evidence" is the orchestrator's discipline, not an engine check (slice integration in S4 and DONE in S5 judge the current tree) | Open, named | S2 |
| L-GF-28 | A paired run (the proof of a documentation finding) is ordered against the finding's review and its resolution, but an evidence run records no tree, so the engine does not know which tree either run saw: unlike a fix-verify's base, the reproduction is not bound to the reviewed tree. A closing round cannot carry a fixed finding, so the fixed document is judged again on a later round's tree | Open, named | S2 |
| L-GF-29 | The runner (GF-RUN-2) runs project code, which can write anywhere: the frozen integrity window fails a run that changes the record or a tracked file outside the caller's claimed ownership, and the runner reports a new untracked file outside the caller's group when the run returns, but that report is not a log event; once committed, such a file is found by GF-OWN-4 attribution | Open, named | S2 |
| L-GF-30 | A paired run (the proof of a documentation finding) is one command the orchestrator chooses: the engine checks that it failed as a reproduction and then passed, not that it is a test of the finding, nor that its failure was an assertion | Open, named | S2 |
| L-GF-31 | Section 4.5's rule that a rescope cite a message id is not built in S2: a rescope is checked for its group only (GF-OWN-5) | Open, named | S2 |
| L-GF-32 | Semgrep, Gitleaks and Trivy are not installed in this environment: the runner checks their pinned forms, but their runs fail as unverifiable here until S4a installs and pins them (design 17.5, 18.4); a delivery report must not pass while they are unverifiable | Open, named | S2 |
