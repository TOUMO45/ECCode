# Pre-registered protocol: Sonnet at n=10 on every task

Committed and pushed before any run of this batch starts; the git commit timestamp is the registration.

**Why.** The Sonnet-specific conclusions in `2026-10-22-sonnet-crossmodel.md` and `2026-10-22-sonnet-grid-completion.md` rest on n=3 per variant and are marked unsettled. This batch settles them, or shows they do not hold.

**Design (fixed in advance).**
- Model: `claude -p --model sonnet`, the same agent command shape as the earlier runs:
  `cat PROMPT.md | claude -p --model sonnet --allowedTools "Read Grep Glob Edit Write Bash(npm test) Bash(node --test*) Bash(pytest*) Bash(go test*)"`
- Tasks: all 8 built-in tasks (csv-sum, dedupe-objects, fix-last-page, go-clamp, py-kebab, py-page-id, relative-time, slugify-reuse).
- n = 10 per variant per task (160 runs), 540 s timeout per run.
- Primary outcome: lines added per run. Secondary outcomes: hidden checks passed, dependency additions, test files changed.
- Analysis:
  - per task, the harness's permutation test on lines added (exact where enumerable, otherwise seeded Monte Carlo);
  - across the batch, the stratified permutation test (labels shuffled within each task, seeded) via `eccode bench tally`.
- Reporting: the report is committed verbatim whatever it shows, including nulls and reversals.
- Stopping rule: no further Sonnet sampling on these tasks after this batch. Sonnet conclusions rest on this batch.
