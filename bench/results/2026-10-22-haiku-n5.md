# Paired run: 2026-10-22, claude-haiku (headless), n=5

> **Follow-up.** Every task in this file was later run at n≥10 per variant ([2026-10-23-haiku-n10-remaining.md](2026-10-23-haiku-n10-remaining.md), [2026-10-23-haiku-n10-replication.md](2026-10-23-haiku-n10-replication.md)), and the two headline tasks at a fixed-protocol n=25 ([2026-10-23-haiku-n25-preregistered.md](2026-10-23-haiku-n25-preregistered.md)). This file's runs stay in the record and in the all-data stratified test (`eccode bench tally`); its small-n figures are not the basis of any conclusion.

Executed with `eccode bench --runs 5` on the three built-in tasks (30 agent
runs). What it shows, honestly read:

- **Hidden checks: 60/60 passed in both variants.** On tasks this small, the
  bare model is already correct; the discipline's value shows elsewhere.
- **Tests: 15/15 runs with the skill shipped a test, 13/15 without** (the
  bare variant skipped the test twice on csv-sum).
- **Diff size: smaller with the skill where reuse exists.** relative-time has
  a `plural()` helper to reuse: −13 median lines (31 vs 44). fix-last-page is
  already minimal: −1. csv-sum: +1 (noise).
- **Dependencies: 0/30 runs added one** in either variant; these tasks don't
  tempt Haiku into libraries. The scripted-agent tests in `tests/bench.test.js`
  prove the harness does catch dependency bloat when it happens.
- **Cost of the discipline: ~3−6s more per run** (longer prompt).

n=5 per cell is still small; direction is consistent with the n=2 run.
Numbers worth quoting need more tasks, more runs and a stronger model.
