# Task: complete a task and approve a gate without writing JSON by hand

Two steps of every piece of work make the agent write a JSON file from memory, and weaker agents get the fields
wrong. Add a short form for each. The long forms keep working unchanged.

1. `eccode task complete <task> --actor <owner> --done "<what is true now and how the check shows it>"`
   - Builds the handoff from the record, the same way `eccode handoff draft` fills it in, with the `--done` text as
     the completed work. The handoff's context is the text of `--notes "<text>"` if given, otherwise the sentence
     "No decisions or constraints beyond the task text."
   - Every existing handoff rule still applies to the result (for example: a passing check after the claim must
     exist, the completed-work text has a minimum length). A handoff that breaks a rule is refused as today.
   - `--handoff <file>` still works.

2. `eccode gate review <gate> --actor <reviewer> --approve --summary "<verdict in one or two sentences>"`
   - Builds an approving review from the record: one criterion for each acceptance criterion of the tasks under
     review (the phase's tasks for a phase gate, otherwise all tasks; a single general criterion if there are none),
     each marked met and citing every passing command run this reviewer recorded since the gate's latest submission.
   - Every existing review rule still applies to the result. So a reviewer who has run no check of their own is
     refused, and so is the author of the work. The gate then stays submitted.
   - `--approve` without `--summary` is refused and records nothing. `--approve` on a gate that is not submitted is
     refused with exit 2 and a message, not a crash.
   - `--file <review.json>` still works.

Show both short forms in the CLI help. Keep the existing test suite passing (`npm test`) and add tests for the new
forms.
