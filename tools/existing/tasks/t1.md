# Task: three command-line fixes

1. **Missing input file.** Commands that read a JSON file named by the user (`eccode plan validate <file>`,
   `eccode memory add --file <file>`, `eccode improve propose --file <file>`, and every other command that loads a
   JSON input file) crash with "internal error" and a stack trace when the file does not exist. A missing file is the
   caller's mistake. Refuse it the way other mistakes are refused: code `NOT_FOUND`, a message that names the file as
   the user typed it, exit 2, no stack trace. A file that exists but is not valid JSON keeps today's `INVALID_JSON`
   refusal.

2. **Version.** `eccode --version` prints the version from `package.json` and nothing else, and exits 0.

3. **A failed check must not exit 0.** `eccode evidence run ... -- <command>` exits 0 even when the command fails,
   so a script chaining commands reads "recorded" as "passed". Keep recording and printing the run exactly as now,
   but exit 3 when the recorded run did not pass. One exception: a run recorded with `--purpose reproduction` is
   expected to fail and keeps exit 0. A passing run exits 0.

Keep the existing test suite passing (`npm test`); where an existing test asserts the old behaviour, update it. Add
tests for the new behaviour.
